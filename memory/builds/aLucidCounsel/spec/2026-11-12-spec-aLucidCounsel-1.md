# ORCH-aLucidCounsel-1 — the report is analysis and advice, not an inventory of the dashboard

**Status:** CLOSED · rev-3 · 2026-11-12 · node a · Tier-2 · base 243c00b8 · streams orchestration · review 2026-11-12-review-aLucidCounsel-2 · landed 409c388

## 1. Goal

The owner's verdict on the delivered reports: they read as an enumeration of the data points
exported from the dashboard and add little beyond it. The tool was meant to produce deep analysis:
every data point cross-referenced, conclusions and recommendations drawn, reviewed for correctness,
and written as one fluent report in which an analyst advises the client on running their account.
This unit changes the agent's instructions so that the default report is that.

## 2. Scope (IN)

- S1. `skill/analysis-playbook.md`, new: the analysis method. Account model, decompose and locate,
  hypotheses tested against the data, a disposition for every finding, advice, the worksheet shape,
  and category lenses.
- S2. `skill/SKILL.md`: a new Flow step 3b that produces an internal analysis worksheet before any
  drafting; step 4 writes from the worksheet; a new step 4b reviews the reasoning with an
  independent reviewer before the closer; fan-out analysts return worksheet slices, not prose; the
  coverage note stops asking for every anomaly to be listed.
- S3. `skill/report-template.md`: a "What the report is for" standard and a new Structure. A short
  version first, then insight-led sub-sections inside each platform section, then `## Data notes`
  for required disclosures, then prioritized recommendations with owner, expected effect and check.
  The per-metric bullet list and the `## Analytical insights` inventory are removed.
- S4. The Rentex October 2026 report regenerated by the new instructions as the acceptance
  specimen, with its reasoning review on file.
- S5 (rev-2). The fixes from the build review: a levels pass and a no-comparison branch in the
  method, hypotheses tested against their own predictions, a subagent contract and a fallback for
  the reasoning review, no measured figures in Recommendations, derived sentences placed inside the
  insight, step 2a opened to analysis-driven requests, and placeholder examples in place of client
  figures.

## 3. Non-goals (OUT)

- No change to any script, to the facts schema or to the closer. The closer already allows this
  shape; section 4 records why.
- No citing of ledger or trend figures inside the single-period report. They do not trace there.
  Follow-up ORCH-aLucidCounsel-2.
- No machine check of report quality. A gate cannot judge an argument. Follow-up
  ORCH-aLucidCounsel-3 covers the one structural check that could be gated.
- The trend report keeps its own facts and is only touched where the Flow text names the new steps.
- Deferred by the build review to the backlog (ORCH-aLucidCounsel-4 to -11): a cross-platform step
  and report section, continuity with the previous report, an interactive question step for the
  account team, contribution figures from the analyzer, lenses beyond search, closer hardening for
  the cases the review reproduced, and derived metrics for trend facts.

## 4. Design

### Diagnosis

Three instructions produced the enumeration, each verified in the files at base 243c00b8.

| Source | Instruction | Effect |
|---|---|---|
| `skill/report-template.md` Structure | "one bullet per headline metric worth featuring" | A metric list per platform |
| `skill/report-template.md` `## Analytical insights` | wins, losses and anomalies as three lists, one anchored line each | A findings list |
| `skill/SKILL.md` Notes, Coverage | "surface every finding with confidence normal and every anomaly" | Every info-level finding printed |

Nothing in the Flow asked the agent to analyze. Step 3 chose single-pass or fan-out and step 4
filled the template, so the only path from facts to prose was transcription.

### What the closer actually requires

Read from `skill/scripts/Test-ReportNumbers.ps1` (`Invoke-Closer`, `Split-Sections`): numbers in a
platform section and its deeper sub-sections trace against that platform; a section with no platform
traces against all facts; a finding's own figures trace only on the line carrying its anchor;
surfacing is forced only for findings of severity major or above, `requiresDownstreamData` findings
and comparison caveats. A narrative with `###` insight sections inside the platform section, and a
`## Data notes` section for the forced items, therefore passes unchanged. The Rentex specimen
confirms it: 112 numbers traced, 0 violations.

### The new flow

1. Step 3b writes `<out>\<stamp>-<slug>-analysis.md` following the playbook. Every finding, headline
   metric and breakdown gets a disposition: `evidence`, `required`, `noted` or `dropped`.
2. A figure the argument needs and the facts lack is requested through step 2a. The agent still
   does no arithmetic.
3. Step 4 writes the draft from the worksheet in the template's new shape.
4. Step 4b spawns one fresh-context reviewer with the facts, draft, worksheet, playbook and template
   paths and the voice, under a fixed subagent contract (open only the named files, quote only facts
   strings, compute nothing). It writes its own top three points from the facts before reading the
   draft, then returns problems under six heads: support, logic, coverage, advice, value and flow,
   no arithmetic. The agent fixes the worksheet and the draft, logs each finding in the worksheet,
   and re-checks every sentence it changed. `--fast`, or a reviewer that cannot run, means a
   self-review that the delivery message declares.
5. The closer runs as before.

### Files touched (estimate)

`skill/analysis-playbook.md` (new), `skill/SKILL.md`, `skill/report-template.md`, this build folder,
`memory/DECISIONS.md`, `memory/backlog/ORCH.md`, `.claude/SESSION-KICKOFF.md` (pointer map row).

### Alternatives rejected

- Enriching the analyzer with more finding rules. More findings feed the same list. The missing
  step is reasoning across findings, which is the model's job.
- Relaxing the closer to let the model compute. The no-arithmetic invariant is what makes the
  report trustworthy; the derived-metric tool already covers figures the argument needs.
- A reviewer that rewrites the report. It would add unverified numbers and a second voice. The
  reviewer returns problems only.

## 5. Production-readiness checklist

- security: the worksheet is a new written file; the playbook and step 3b bind it to the credential
  rules, and the reviewer receives paths to facts, draft, worksheet and playbook only.
- perf / scale: one extra subagent per report by default; `--fast` skips it.
- a11y: N/A — a markdown report.
- i18n: N/A — English reports only today.
- error / empty / loading states: a quiet period gets a short report (playbook Step B, template).
  The untrusted-comparison rules are unchanged, but the new shape leads with figure-free sentences
  the closer cannot see, so Step B has a no-comparison branch and review check 1 covers comparative
  wording (rev-2). A reviewer that cannot run falls back to a declared self-review.
- observability: the worksheet is the audit trail of the reasoning and stays in the out dir.
- risks: recommendations are not traced by the closer, so the template forbids measured figures there
  and the review's sixth check covers it. Nothing mechanical proves steps 3b and 4b ran; the delivery
  message states which review ran. Two process deviations are recorded here. (1) The owner's request
  in conversation on 2026-11-12 was taken as scope approval and the build ran before an adversarial
  spec review; the build review of rev-2 (three reviewers, three verifiers, one adjudicator) was run
  at the owner's instruction before landing and is on file. (2) AGENTS.md section 1 says "Tier-2
  ships behind a default-OFF flag or as inert defaulted data". This unit changes the default report
  with no flag: the owner asked for it as the default, a flag would mean two parallel instruction
  paths, the change is instruction text only and one revert restores the old behaviour. The
  regenerated specimen is the in-place verification.
- testing + left-shift gates: all existing legs stay green; `Test-Forecast` C8 reads the template's
  Estimates block, which is unchanged. No new gate, see section 3.
- migration / rollback: documentation only; reverting the merge restores the old instructions.
- user docs: `skill/SKILL.md` and `skill/report-template.md` are the user docs and are the change.

## 6. Acceptance criteria

- AC1. When the Rentex October 2026 facts are reported by the new instructions, the draft has no
  per-metric bullet list and no findings list, every insight section ends in a consequence, and the
  closer passes it.

- AC3. When an independent reviewer checks the specimen against the facts, every blocker it raises
  is fixed before publish, and its verdict is on file under `reviews/`.
- AC4. When `bash tools/run-gates.sh` runs on the branch, every leg passes with suite counts
  unchanged.
