## 4. Synthesis (verbatim)

GO-WITH-CHANGES

### Must-fix before build

1. **S1 + §4 Inventory paragraph (the `Ws-Recv` fix) + a new reset seam.** The held task must be state, not a cache. Corrected rule: "`Ws-Recv` holds the pending `ReceiveAsync` in `$script:pendingRecv`. The slot is cleared when (a) the task completes and its `Result` has been read, (b) the task ends `Faulted` or `Canceled`, or (c) the completed result's `MessageType` is `Close`. `Connect-Ws` sets `$script:pendingRecv = $null` as its FIRST statement, before constructing the new `ClientWebSocket`. A `Reset-FetchState` function, defined above the `-DefineOnly` return at `:365`, clears `$script:pendingRecv`, the run-budget accumulator and the reconnect counter; the run body calls it once at start and every suite case calls it in setup." Add **AC14**: a stub whose pending receive faults, then a reconnect, and the next `Ws-Recv` returns a live frame and `Connect-Ws` obtains a `socketId`. Add **AC15**: a reconnect mid-wait does not resurrect a pre-reconnect frame. Without this, one socket death deafens the receiver for the whole run and every remaining widget ends `incomplete`.

2. **§4 state machine steps 4/5/6 and the "Attribution is positional" paragraph.** The drain cannot remove a frame that has not arrived yet. Corrected rule: "Any widget that ends WITHOUT a verdict (`incomplete`, `transport-failed`, `socket-lost`, `run-budget-exhausted`, `partial-pages`) forces `Connect-Ws` before the next widget is fetched; the new `socketId` orphans the abandoned compute so it can never deliver on the live socket. In addition `Fetch-Widget` maintains a run-scope `$script:outstandingComputes`, incremented on every such outcome and reset to 0 by a successful reconnect. The classifier becomes `Get-WidgetOutcome $verdict $rows $budgetLeftMs $outstandingComputes`: while `$outstandingComputes` is greater than 0, `RESOLVED` with zero rows yields `incomplete` (reason `stale-verdict-risk`), never `empty-resolved`." Replace the attribution sentence with: "Attribution is positional and is sound only because fetching is sequential, step 1 drains first, AND every widget that ends without a verdict forces a reconnect, so no compute is ever left outstanding across a widget boundary." Update §5 risks to state the same. Add **AC16**: a stubbed socket delivers widget A's `RESOLVED` during widget B's wait; B must end `incomplete`, not `empty-resolved`, and `meta.extractionComplete` must be `$false`.

3. **S5/S7 + §4 Data model `reason` enum (the pagination loop at `:155-159`).** Corrected rule: "The pagination loop distinguishes a faulted page from a last page. On a failure marker, or on any page whose `.data.widget.data` is absent while the previous page's `pageInfo.hasNextPage` was `$true`, the widget ends `incomplete` with reason `partial-pages`, recording `pagesFetched` and `endCursor` in `meta.incompleteWidgets`; rows already collected are still emitted. A widget is NEVER classified `filled` when any page fetch faulted or when the loop terminates with `hasNextPage -eq $true`. A failed page is retried under the same budget as page 1." Add `partial-pages` to the reason enum in §4 Data model. Add **AC17**: `Invoke-GQL` stubbed to succeed on page 1 and return the marker on page 2 puts the widget in `meta.incompleteWidgets` with reason `partial-pages` and `meta.extractionComplete` `$false`. Today that fault aborts loudly; without this amendment it becomes a silent 500-of-2000-row truncation that the closer certifies.

4. **S4 + §4 transport paragraph (every blocking call, not just `Invoke-GQL`).** Corrected rule: "Every network call reachable during a run is explicitly bounded. `Mint-Jwt`'s `Invoke-RestMethod` (`:57`) and the share-page fetch (`:372`) take an explicit `-TimeoutSec`. `ConnectAsync` (`:83`) and `SendAsync` (`:78`) use bounded `.Wait($ms)` and treat expiry as socket-lost. `Connect-Ws`'s discovery loop is bounded by a wall-clock `handshakeMs` from `Get-FetchPlan`, not by 8 fixed 5000 ms slices. State the constant for each. The §3 non-goal 'no retry of the share-page fetch or the structure query' constrains RETRY only; it does not exempt either call from a timeout." Add a documented check to `Test-Extractor.ps1` that reads `Get-SwydoReport.ps1` as text and asserts no `Invoke-WebRequest`/`Invoke-RestMethod` call site lacks `-TimeoutSec` and no `.Wait()` is called with no argument. Without this, the 500 s JWT re-mint fires from inside a widget re-query and hangs the run past both budgets.

5. **§4 state machine step 6 (`Connect-Ws` contract).** Corrected rule: "`Connect-Ws` nulls `$script:socketId` before `ConnectAsync` and returns `$true` only when a `socketId` was obtained; it returns `$false` on a connect fault or on no `kind:2` within `handshakeMs`, instead of throwing into a bare `catch{}`. No query is ever fired while `$script:socketId` is `$null`: the widget ends immediately with reason `socket-lost`. After `maxReconnects` consecutive failed reconnects the run stops fetching and writes the document with the remaining widgets `incomplete` reason `socket-lost`. Handshake wall clock is charged to `totalWaitedMs`." Add **AC18**: with a stub that never emits `kind:2`, the widget ends `socket-lost` within the handshake bound (not `budget-exhausted` at `MaxWaitSec`) and the reconnect attempt count equals `maxReconnects` exactly.

6. **S5 + §4 Files touched (`Fetch-Widget`'s signature and all six call sites).** Corrected rule: "The new signature is `function Fetch-Widget($w, $dr, $cp, $opt)`, where `$opt` is `@{ maxWaitSec=<int>; plan=<Get-FetchPlan result>; budget=<run-budget state> }` and `$null` means 'use the run defaults'. The attempt-count positional slot is REMOVED, not repurposed, so no leftover integer can bind to `$dr`." Give the post-change form of every site verbatim in the Files-touched table: `:307` `Fetch-Widget $w (New-RelDateRange (-1*$n) 'month') $null $script:fetchOpt`; `:423` same with `(New-RelDateRange -12 'month')`; `:442` same with `(-1*$ceiling)`; `:495` `Fetch-Widget $w $null $null $script:fetchOpt`; `:504` per should-fix 1; `:437` via `Probe-WidgetMonths`. Add **AC19**: with `Invoke-GQL` stubbed to record `$vars`, `Fetch-Widget` invoked the way the run body invokes it sends `sid`/`dr`/`cp` byte-identical to pre-change (`dr` resolves to `$script:dr`), and the effective budget at each site equals the value `Get-FetchPlan` derived from `-MaxWaitSec`. Left as-is, `Fetch-Widget $w 5` silently means either a 5-second budget or `dr=5`.

7. **S4 + §3 non-goals (the failure marker's shape and every `Invoke-GQL` caller).** Corrected rule: "On retry exhaustion `Invoke-GQL` returns `[pscustomobject]@{ __fetchFailed=$true; reason=<string>; attempts=<int>; lastError=<string> }` - an object, never a JSON string, so a caller that forgets to branch faults loudly at `ConvertFrom-Json` rather than parsing to nulls. Every caller branches on `$r -is [pscustomobject] -and $r.__fetchFailed` BEFORE `ConvertFrom-Json`: `:147` ends the widget `incomplete` reason `transport-failed`; `:156` per must-fix 3; `:307` returns probe state `unsettled`; `:387` throws `structure query transport fault: <reason> after <attempts> attempts`. `Invoke-GQL` gains `-NoRetry`, passed by the share-page fetch and the structure query." Re-word the §3 non-goal to: "No RETRY of the share-page fetch or the structure query. Both still take an explicit `-TimeoutSec`, and both still throw on a transport fault, which is correct for a bad link." Add **AC20**: a transport fault on the structure query still throws at startup with a transport-shaped message.

8. **S8 + new S8b + §4 Files touched (the trend chain).** Corrected rule: "`$tdoc.meta` (`:474-480`) gains the same three fields. `Get-TrendMonthCells` gains a distinct `windowStatus='unsettled'`, fed from the per-widget verdict, so a budget-exhausted window is never recorded as `overshoot-empty`; an `unsettled` window contributes no cells and is not admissible coverage evidence. `Update-SwydoLedger.ps1` refuses to merge trend facts whose `meta.extractionComplete -eq $false`, in the same shape as the existing `providerFilter` refusal at `:186-187`. `ConvertTo-SwydoTrendFacts.ps1` carries `extractionComplete`/`incompleteWidgets` into its meta, and `Analyze-SwydoTrend.ps1` copies them into `$factsDoc.meta` at `:337-343`, so S10's closer gate covers the trend report path." Add `ConvertTo-SwydoTrendFacts.ps1`, `Update-SwydoLedger.ps1` and `Analyze-SwydoTrend.ps1` to Files touched, and `Test-TrendFacts.ps1`, `Test-Ledger.ps1`, `Test-TrendAnalyze.ps1` to S12. Add **AC21**: a trend document with `extractionComplete:false` is refused by `Update-SwydoLedger.ps1` and, if analyzed, yields an `incomplete-extraction` violation from `Invoke-Closer`. Without this, AC10's absent-key rule permanently exempts every trend report from the gate.

9. **S11 + §10 reuse audit (`Probe-WidgetMonths` has three callers).** Corrected rule: "`Probe-WidgetMonths` returns `[ordered]@{ state=<has-months|rejected|empty-resolved|unsettled>; months=@(<month keys>) }`. Its callers are `:315` and `:322` inside `Get-WidgetCeiling`, and `:437`, the cached-ceiling revalidation. `:437` reads `.months` and passes that to `Test-TrailingContiguous`, and treats `unsettled` as 'cache not validated', falling through to `Get-WidgetCeiling` rather than throwing - it has a safe fallback the bisect does not. The abort-on-`unsettled` rule applies ONLY inside `Get-WidgetCeiling`'s ladder and bisect. The accept/reject decision moves into a pure `Test-CeilingStillValid $probeResult $minRun` defined above `:365`." Correct §10 to name all three call sites. Extend **AC11** to cover the revalidation caller. Left as-is, every cached ceiling is silently judged stale and the full ladder plus bisect re-runs per widget per run.

10. **§3 Migration + a new S11b (the ceiling cache).** Corrected rule: "The ceiling-cache entry gains `probeVersion=2`. Any entry lacking `probeVersion -ge 2` is ignored, so the first post-change trend run re-derives every ceiling instead of inheriting a false one from the emptiness-based prober. On a cache HIT the entry is written back with its ORIGINAL `discoveredAt`; `:441` must not re-stamp it with `$now`, or the 30-day TTL never expires for any client whose trend runs monthly." Amend Migration to: "None for extraction and facts documents. The ceiling cache is versioned: pre-change entries are ignored exactly once, by design." Without this, S11 never reaches any client that already has a cache, and a false 12-month ceiling propagates into `coverage.ceilingMonths` and the ledger indefinitely.

11. **S8 + AC7/AC8/AC12 + §7 (make the completeness block reachable offline).** Corrected rule: "The three meta fields are computed by a pure `Get-ExtractionCompleteness $outcomes $plan $budgetState`, defined ABOVE the `-DefineOnly` return at `:365`, returning exactly `[ordered]@{ extractionComplete=<bool>; incompleteWidgets=@(...); fetchBudget=@{...} }`. The run body does nothing but splice that block into `$doc.meta` and `$tdoc.meta`." Rewrite AC7, AC8 and AC12 as assertions against that helper, and add two trap cases: an outcome set with no incomplete widgets yields `extractionComplete=$true` with `incompleteWidgets` an `@()`-wrapped EMPTY array (`@($null).Count -eq 1`, so a null must never masquerade as one entry), and an outcome set of only `empty-resolved` yields `$true`. Record the residual run-body splice in §7 as a documented check, not a gate. As written, all three ACs sit below `:365` and no suite can observe them.

### Should-fix

1. **§4 - the reconcile loop at `:501-506` is unaddressed.** Add: "The reconcile loop is removed; its function now lives inside `Fetch-Widget`'s verdict wait. If retained, it skips any widget already classified `filled`, `empty-resolved`, `rejected` or `incomplete`, and each widget's outcome record is written exactly once (first write wins), so `meta.extractionComplete` is deterministic for an unchanged report." Left unstated, ten genuinely empty widgets each burn three extra full budgets, and a later round can overwrite a settled outcome, making publish/no-publish depend on round timing.

2. **§4 step 1 - pin the drain's implementation, and gate the reconnect cap.** Add: "The drain reads with a non-zero `plan.drainSliceMs` (default 50 ms) and loops until a slice returns empty; `Ws-Recv 0` is forbidden, because `Task.Wait(0)` returns false on a frame already sitting in the OS buffer and silently no-ops the drain. A `kind:4` seen during the drain is still answered with `kind:5`." Add the AC pair §5 already claims exists: a stubbed receive queue holding a leftover `kind:3` is not consumed as the next widget's verdict, and with `Connect-Ws` stubbed to fail the reconnect attempts equal `maxReconnects` exactly before the widget ends `socket-lost`.

3. **§7 - name the review-artifact path in the plural.** Tier-2 review artifacts for this unit land in `memory/extraction/builds/2026-08-04-EXTR-aPatientHarvest/reviews/`. Hygiene check 4 sanctions `D:reviews` only, so the singular `review/` that AGENTS.md:167 prescribes reds the memory-hygiene leg of `tools/run-gates.sh` and blocks the landing. File a backlog row to fix AGENTS.md:167 to `reviews/`; that edit is outside this unit.

### Explicitly accepted risks

1. **AC13's byte-identical guarantee stays a manual live check.** No offline gate can prove it; AC19 (recorded `$vars` identity) is the only mechanical proxy, and it covers the request, not the emitted document.
2. **The run-body splice of the meta block remains ungated wiring.** Must-fix 11 pushes all logic into a pure helper, but the two lines that place the block into `$doc.meta`/`$tdoc.meta` are covered only by the live run and the documented check.
3. **Forcing a reconnect after every unverdicted widget costs one handshake each.** Charged to `totalWaitedMs` and bounded by `maxReconnects`; accepted as the price of closing the mis-attribution class, which is silent and publishes wrong numbers.
4. **The `kind:3` status enum is still only partially mapped.** Any status other than `RESOLVED` or `REJECTED` is treated as "no verdict", so the widget waits out its budget and ends `incomplete`. Conservative in the blocking direction, and only two statuses were ever observed.
5. **The 1 MiB `$script:buf` ceiling and continuation-fragment handling stay known limits**, per the existing §3 non-goal; observed frames are about 120 bytes.
6. **No remote CI guards any of this.** The whole bar is self-run per AGENTS.md §7's standing compensating control, and a skipped run counts as red.

## 5. Disposition

All eleven must-fixes and all three should-fixes are folded into spec rev-3, except should-fix 3,
which is a governance-doc defect outside this unit and is filed as a backlog row instead:

only `reviews/`, so following the playbook literally would red the memory-hygiene gate leg.
The six accepted risks are recorded in spec section 5 rather than being closed.
